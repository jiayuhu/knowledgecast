# KnowledgeCast 设计文档

## 1. 结论

定位：面向讲师 / 培训师 / 知识型从业者，把碎片知识快速整理成**可讲、可发、可复用**的培训网页。

核心链路：`碎片知识输入 → AI 结构化整理 → 生成培训/宣讲内容 → 以网页形式输出`

首选客群：个人讲师、独立顾问、培训博主。

扩展客群：企业内训/L&D、销售赋能、产品赋能、创业者内部分享、知识型内容创作者。

核心痛点：
1. 先找到独特且有价值的培训框架
2. 再把零散素材/经验/想法消化成结构化内容

产品边界：不是泛知识管理，也不是大而全内容平台。

核心闭环：

`碎片输入 → 选择培训框架 → AI 生成幻灯片 → 对话式迭代 → 私密分享 / 导出`

## 2. MVP 范围

### 2.1 包含

- 文本/链接/Markdown 碎片输入（自动识别类型）
- 批量倾倒碎片，快速采集
- 5 套预设培训框架模板（问题解决型、概念讲解型、经验分享型、技能教学型、产品介绍型）
- AI 按框架将碎片组织为幻灯片（每页含标题、要点、讲者备注、时长预估）
- AI 对话式迭代调整（自然语言指令，非直接编辑）
- 版本历史，支持回退
- 生成培训网页，幻灯片式展示
- 私密链接分享 + 邮箱验证码访问
- 讲者备注（讲师视角展开，学员视角折叠）
- 水印保护
- 草稿、已生成、已分享状态管理

### 2.2 不包含

- 语音转文字录入（后续版本）
- 在线直接编辑幻灯片内容
- 多人协作编辑
- 内容商店或公开市场
- 复杂 CMS 能力
- 原始 HTML 源文件下载
- 公开匿名访问
- 移动端 App

### 2.3 后续演进

- 导出 PPTX
- 讲模式 / 发模式（双视图）
- 自定义框架模板
- 基于已有培训页改编新版本

## 3. 产品定位

KnowledgeCast 不是泛知识管理工具，也不是大而全内容平台。它只解决一个场景：

用户把零散素材输入系统，选择培训框架，AI 把碎片整理成结构化幻灯片，最终以培训网页形式输出。

三个价值点：

- 帮助讲师找到独特且有价值的培训框架
- 降低碎片素材的结构化成本（AI + 框架模板）
- 降低内容分发和更新成本（网页链接即培训材料）

## 4. 用户与场景

### 4.1 首选客群

- 个人讲师、独立顾问、培训博主

### 4.2 扩展客群

- 企业内训 / L&D
- 销售赋能
- 产品赋能
- 创业者内部分享
- 知识型内容创作者

### 4.3 受众

- 内部团队成员、学员、客户

首版聚焦内部培训场景。

## 5. 访问与保护策略

### 5.1 访问模型

`私密链接 + 邮箱验证码`：

1. 创建者生成分享链接
2. 访问者打开链接，输入邮箱
3. 系统发送一次性验证码
4. 验证通过后，短期内可访问
5. 链接可撤销、可过期

### 5.2 保护措施

- 不提供 HTML 源文件下载
- 页面服务端渲染，不暴露源码
- 分享链接可失效、可撤销
- 页面加入访问者邮箱水印
- 接口鉴权和限流（60 次/分钟）
- 审计日志记录访问事件

### 5.3 不做的事

- 不追求绝对防复制
- 不做重型 DRM
- 不做设备绑定
- 不做客户端源码混淆

## 6. 信息架构

### 6.0 导航层

左侧固定侧边栏（w-60，240px），树形结构：

```
📁 工作区 A (可折叠，可拖拽排序)
  ├── 📋 工作集 1 (可拖拽排序，可跨区移动)
  ├── 📋 工作集 2
  └── + 新建工作集
📁 工作区 B
  └── ...
+ 新建工作区
```

- 侧边栏始终可见，sticky 定位在顶栏下方
- 点击工作集跳转到其 Dashboard 页面
- 仅剩一个工作区时，删除按钮隐藏（至少保留一个工作区）
- 工作区下仅剩一个工作集时，该工作集的删除按钮隐藏（每个工作区至少保留一个工作集）
- 工作区和工作集悬停显示改名/删除按钮
- 支持拖拽排序和跨工作区移动工作集

工作集 Dashboard（`/workspace/[id]`）：
- 显示工作区名称 + 工作集名称
- 三卡片入口：采集、整理、发布
- 素材数 / 培训页数统计
- 最近培训页列表（复制链接、预览、继续编辑）
- ⚙ 工作集设置入口

### 6.1 采集层（Capture）

路由：`/workspace/[id]/capture`

- 万用大输入框，自动识别内容类型（文本/URL/Markdown）
- 捕获后 AI 自动生成碎片标题（10 字以内）
- 碎片列表：标题、内容摘要、时间、类型标签
- 点击标题进入内联编辑（人工修改或点击 AI 按钮重新生成）
- 点击内容进入内联编辑
- 悬停显示删除按钮（红色垃圾桶）
- 支持勾选，用于下一步生成
- Ctrl+Enter 快捷提交
- 空状态：引导文案 + 操作提示

### 6.2 整理层（Structure）

路由：`/workspace/[id]/structure`

- 框架选择器：内置 5 套 + 用户自定义模板
- 自定义模板：名称、步骤（顿号分隔）、适用场景，可编辑/删除
- AI 将碎片素材按框架组织为幻灯片
- 每页幻灯片含：标题、3-5 个要点、讲者备注、时长预估
- 讲者备注默认展开
- AI 生成时自动注入工作集的培训主题描述
- 对话式迭代：通过自然语言指令调整
- 生成结果持久化到 localStorage
- 生成后自动展示分享链接卡片（绿色），一键复制
- 空状态：引导「去采集页添加素材」

### 6.3 输出层（Share）

路由：`/workspace/[id]/publish`（讲师视角）+ `/share/[token]`（学员视角）

- 幻灯片式展示，带页码导航
- 顶部：标题、框架名称、总时长预估
- 讲者备注默认展开
- 创建者预览跳过邮箱验证（`?preview=1`），顶部蓝色提示
- 发布页展示培训页列表，支持复制链接和预览
- 空状态：引导「去整理页生成」

### 6.4 传播层

- 私密分享链接
- 邮箱验证码访问
- 链接过期和撤销
- 访问者邮箱水印
- 审计日志

## 7. 交互流程

### 7.1 创建工作流

侧边栏导航 + 页面顶部 action tabs，可自由循环切换：

1. **侧边栏**：选择工作区 → 选择工作集 → 进入 Dashboard
2. **Dashboard**：卡片入口进入采集/整理/发布，或点击设置
3. **采集**：粘贴文本/链接/Markdown，AI 生成标题，存入当前工作集
4. **整理**：勾选素材 → 选择框架（内置或自定义） → AI 生成幻灯片 → 对话式迭代
5. **发布**：复制链接或预览学员视角

Action tabs 在每个子页面顶部显示，含面包屑（工作区名 / 工作集名） + 采集/整理/发布/设置四个标签。可随时切换。

### 7.2 侧边栏交互

- 点击 ▶ 展开/折叠工作区
- 点击工作集名称 → 跳转 Dashboard
- 拖拽工作区标题 → 排序工作区
- 拖拽工作集 → 同区内排序，或拖到其他工作区标题实现跨区移动
- 悬停 → 显示改名（✏️）、删除（✕）按钮

### 7.2 分享流程

1. 创建者生成分享链接
2. 创建者可点击「预览分享页」直接查看（跳过验证，带预览标识）
3. 学员访问时 → 邮箱验证码验证
4. 验证通过后查看培训内容（幻灯片形式）
5. 页面显示访问者邮箱水印
6. 创建者可随时撤销链接

## 8. 编辑策略

首版不做直接编辑，而是通过 AI 对话式迭代调整内容。

用户输入自然语言指令，AI 带着原始素材 + 上轮结果 + 调整指令一起推理，生成新版本。

示例指令：

- 「把第三章展开，加一个案例」
- 「删掉太技术的内容，面向非技术受众」
- 「压缩到 30 分钟」
- 「换成经验分享型框架重新组织」

每次调整保留版本快照，可随时回退到历史版本。

## 9. 数据模型

### 9.1 核心实体

- `Area`：工作区（名称、排序序号），顶层容器，按业务方向划分
- `Workspace`：工作集（名称、培训主题 topic、排序序号、所属 area_id），素材和培训页的归属容器
- `KnowledgeItem`：单条碎片输入（文本/URL/Markdown），归属于一个工作集
- `TrainingPage`：生成的培训页面，包含框架 ID、幻灯片 JSON、时长、版本号
- `Slide`：单张幻灯片（标题、要点数组、讲者备注、预估时长），序列化在 slides_json 中
- `Framework`：培训框架模板。内置 5 套（代码常量）+ 用户自定义（`user_frameworks` 表）
- `IterationHistory`：迭代历史（版本号、用户指令、幻灯片快照）
- `ShareLink`：分享链接和权限状态
- `AccessToken`：访问者短期凭证
- `AuditLog`：访问和操作审计记录

工作集的培训主题（topic）描述培训目的和受众，作为 AI 生成时的上下文输入。

### 9.2 幻灯片数据结构

```typescript
type Slide = {
  title: string;           // 页面标题
  bullets: string[];       // 3-5 个要点
  speakerNotes: string;    // 讲者备注
  estimatedMinutes: number; // 预估时长
};

type TrainingContent = {
  title: string;
  framework: string;       // 框架 ID
  totalMinutes: number;    // 总时长
  slides: Slide[];
};
```

### 9.3 状态流转

`KnowledgeItem`：draft → archived

`TrainingPage`：processing → ready

`ShareLink`：active → revoked

## 10. 系统架构

- 前端：Next.js 15 + React 19 + Tailwind CSS v4
- 后端：Next.js API Routes + Server Components
- 数据库：SQLite + Drizzle ORM + Drizzle Migration（`drizzle/` 目录，`npm run db:generate` 生成，启动时自动执行，增量迁移不丢失数据）
- AI：DeepSeek API（默认）/ OpenAI API（可选切换）
- 部署：Vercel / Node.js 服务

数据库命名约定：

- 表名使用 `snake_case`
- 列名使用 `snake_case`
- TypeScript 代码使用 `camelCase`

## 11. AI 设计原则

### 11.1 框架驱动

AI 不是自由发挥，而是按照预设培训框架的结构组织内容。框架定义清晰的章节顺序和逻辑递进关系，确保输出结构一致、可预期。

### 11.2 幻灯片输出

AI 输出结构化的幻灯片 JSON（而非自由文本），每页包含标题、要点、讲者备注和时长预估。要点简洁（3-5 条），便于口头展开。讲者备注为讲师提供实操指导。

### 11.3 对话式迭代

用户通过自然语言指令调整内容，而非直接编辑文本。AI 每次迭代携带完整上下文（原始素材 + 上轮结果 + 调整指令），保证结构调整的连贯性。

### 11.4 版本管理

每次调整保留快照，用户可随时回退。版本历史可视化，清晰展示每次改了什么。

### 11.5 稳定输出

- AI 输出通过 Zod Schema 校验
- 温度参数设为 0.1，保证一致性
- JSON 模式强制结构化输出

## 12. 安全与风险

### 12.1 主要风险

- 访问者可手工复制阅读到的内容
- 截图无法彻底禁止
- 共享链接可能被转发
- AI 生成内容可能不准确

### 12.2 处理方式

- 将「防批量下载」作为目标，而非「绝对防泄露」
- 用访问控制、过期机制、水印和审计记录提高滥用成本
- AI 输出标记为可迭代草稿，讲师审核后再分享
- 通过版本管理减少错误传播

## 13. UI 设计规范

### 13.1 圆角

| 元素类型 | 圆角值 | Tailwind |
|---------|--------|---------|
| 页面容器/主卡片 | 12px | `rounded-xl` |
| 输入框/按钮/小卡片 | 8px | `rounded-lg` |
| 标签/Badge | 6px | `rounded-md` |
| 全宽区域分隔 | 0 | 无圆角 |

### 13.2 留白

- 页面两侧：32px（`px-8`）
- 最大内容宽度：1280px（`max-w-7xl`）
- 三栏布局：`grid-cols-[280px_1fr_380px]`

### 13.3 导航

- 侧边栏：w-60（240px），sticky 定位在顶栏下方，树形结构
- Action tabs：面包屑 + 操作标签合并一行，竖线分隔
- 拖拽：光标 grab/grabbing，支持排序和跨区移动

### 13.4 阴影

- 静态卡片：无阴影，用 `border border-gray-200` 区隔
- 浮层（dropdown/modal）：`shadow-lg`
- 不使用自定义大阴影

### 13.4 字体层级

| 层级 | 样式 | 用途 |
|------|------|------|
| Display | `text-3xl font-bold tracking-tight` | 页面标题 |
| Heading | `text-lg font-semibold` | 区块标题 |
| Label | `text-xs font-medium uppercase tracking-wide` | 字段标签/微标 |
| Body | `text-sm leading-relaxed text-gray-700` | 正文 |

### 13.5 色彩

| 用途 | 颜色 |
|------|------|
| 背景 | `#fafafa` |
| 卡片 | `#ffffff` |
| 主文字 | `#171717`（neutral-900） |
| 次文字 | `#737373`（neutral-500） |
| 边框 | `#e5e5e5`（neutral-200） |
| 品牌强调 | `#2563eb`（blue-600） |
| 成功 | `#16a34a`（green-600） |
| 处理中 | `#d97706`（amber-600） |

### 13.6 按钮层级

| 层级 | 样式 | 用途 |
|------|------|------|
| Primary | `bg-blue-600 text-white hover:bg-blue-700` | 生成、发布 |
| Secondary | `border border-gray-300 text-gray-700 hover:bg-gray-50` | 保存、刷新 |
| Tertiary | `text-gray-600 hover:text-gray-900` | 取消、关闭 |

## 14. 成功标准

MVP 验证标准：

- 用户能快速采集碎片素材
- 用户能理解并选择合适的培训框架
- AI 能按框架把碎片组织成可讲幻灯片
- 用户能通过自然语言有效调整内容
- 用户愿意把分享链接发给学员
- 学员能顺利验证并阅读培训内容
- 用户觉得它比手工做 PPT 更省时间

## 15. 结论

KnowledgeCast 的核心不是「记录知识」，而是「把碎片酿成一堂课」。

首版坚持：

- Web 优先
- 框架驱动（5 套预设模板）
- AI 对话式迭代（非直接编辑）
- 幻灯片输出（标题 + 要点 + 讲者备注）
- 私密访问
- 内部培训场景优先
- 防源文件下载，不追求绝对防拷贝
