# KnowledgeCast 整理环节增强设计

## 1. 结论

对整理（Structure）环节做三项增强，把体验从「能跑」提升到「好用」：

1. **版本历史 + 回退** — 每次 AI 生成/迭代自动保存快照，用户可查看和恢复到任意版本
2. **素材覆盖分析** — 生成前做轻量数量提示，生成后在结果中标注语义级缺口
3. **轻量文本编辑** — 标题、要点、讲者备注可内联编辑，结构变更仍走 AI

## 2. 版本历史

### 2.1 触发规则

每次 AI 生成或迭代都自动创建版本，用户无需手动操作。

### 2.2 UI 位置与布局

在整理页的「生成按钮区」和「幻灯片展示区」之间，插入版本栏。仅当存在历史版本时显示。

**收起态：**

```
版本历史 ▸  v3 / 共 5 个版本  |  ◀ 上一个  ▶ 下一个  |  ↻ 恢复此版本
```

**展开态：**

点击 `▸` 展开下拉面板，每行一条记录：

```
版本历史 ▾
┌─────────────────────────────────────────────────────────────┐
│ ● v5  2026-05-05 14:30   指令：「把第三章展开，加一个案例」       │
│   v4  2026-05-05 14:15   指令：「删掉太技术的内容」              │
│   v3  2026-05-05 14:00   指令：「压缩到 30 分钟」               │
│   v2  2026-05-05 13:45   指令：「换成经验分享型框架」            │
│ ○ v1  2026-05-05 13:30   首次生成                             │
└─────────────────────────────────────────────────────────────┘
```

- `●` 表示当前版本，`○` 表示历史版本
- 点击历史版本行 → 幻灯片区域切换渲染该版本内容（预览模式）
- 点击当前版本行 → 回到最新版本
- 点击 `◀ 上一个` / `▶ 下一个` → 快速顺序翻看
- 点击 `↻ 恢复此版本` → 确认弹窗 → 将此版本状态回填为当前版本（创建一条新版本记录，指令标注为「恢复到 vX」）

### 2.3 数据模型

利用已有的 `TrainingPage.version` 字段。每次生成/迭代产生新 `TrainingPage` 记录，`version` 为上一版本 +1。

迭代 API 已接受 `previousPageId`，生成时在服务端自动关联版本链。同一工作集的同一框架下，版本按创建时间线性排列。

### 2.4 API 变更

新增一个获取版本列表的接口：

`GET /api/training-pages/[id]/versions`

返回该培训页所属版本链的所有版本摘要：

```json
{
  "versions": [
    {
      "id": "xxx",
      "version": 5,
      "instruction": "把第三章展开，加一个案例",
      "createdAt": "2026-05-05T14:30:00Z"
    }
  ]
}
```

新增 `PATCH /api/training-pages/[id]` 端点，支持更新 `slidesJson` 字段，用于：
- 版本恢复：将目标版本的幻灯片内容写回当前 TrainingPage（同时创建一条新版本记录，指令为「恢复到 vX」）
- 手动编辑保存：更新当前页面的幻灯片内容（不创建新版本记录）

## 3. 素材覆盖分析

### 3.1 生成前：数量级轻量提示

在选择框架后、生成按钮前，显示一行静默提示。纯数量对比，不调 AI：

```
你有 5 条素材，当前框架有 4 个环节。建议每个环节至少 2 条素材。
```

- 素材数 ≥ 环节数 × 2：绿色
- 素材数 ≥ 环节数：黄色
- 素材数 < 环节数：红色

零成本，即时显示。

### 3.2 生成后：AI 语义级缺口标注

生成完成后的幻灯片列表上方，显示覆盖摘要条：

```
⚠️ 素材覆盖：3/5 环节充足。「案例研究」「行动计划」环节素材不足，建议补充相关案例或数据。
```

显示条件：AI 在 speakerNotes 中任意幻灯片标注了素材不足 → 前端解析并汇总。

颜色规则：
- 所有环节充足：绿色边框 + `✓` 图标
- 1-2 个环节不足：黄色边框 + `⚠️` 图标
- 3 个以上环节不足：红色边框 + `✗` 图标

此条不阻塞操作，用户可忽略、可回到采集页补充后重新生成。

### 3.3 Prompt 调整

在现有生成 prompt 中追加一段说明：

```
对每个环节，评估素材是否足够支撑该环节内容。如果某环节素材明显不足，请在该环节第一张幻灯片的 speakerNotes 中以「[素材不足] 建议补充：XX」开头给出具体建议。
```

### 3.4 不做的

- 不在生成前单独做 AI 覆盖分析（额外 API 调用，且预分配结果可能与实际生成不一致）
- 不做逐素材的环节标签（用户无需手动分类，这是 AI 做的事）

## 4. 轻量文本编辑

### 4.1 可编辑范围

| 字段 | 编辑方式 | 保存时机 |
|------|---------|---------|
| 幻灯片标题 | 点击文字变 `<input>` | 回车或失焦 |
| 单条要点 | hover 显示编辑图标，点击进入内联编辑 | 回车或失焦 |
| 新增要点 | 要点列表末尾 `+` 按钮 | 即时 |
| 删除单条要点 | 每条 hover 显示删除图标 | 即时（保留至少 1 条） |
| 讲者备注 | 点击进入 `<textarea>` | 回车或失焦 |

### 4.2 不可编辑范围

以下仍需通过 AI 迭代指令调整：

- 添加/删除/重排序幻灯片
- 更换框架
- 合并、拆分章节
- 预估时长（AI 生成时自动计算）

### 4.3 编辑后保护

手动编辑后，版本栏上方出现轻量提示：

```
⚠ 已手动编辑，部分 AI 迭代可能导致手动修改丢失
```

这是提醒而非锁定——用户可以忽略并继续使用 AI 迭代。

手动编辑内容不自动产生版本快照；但用户可通过正常 AI 迭代（此时手动修改会作为上轮结果的一部分带入迭代上下文）或点击恢复功能之前的 AI 版本来找回。

### 4.4 数据保存

编辑后直接更新当前 TrainingPage 的 `slidesJson` 字段。前端用本地 state 驱动即时渲染，保存通过 debounce（500ms）发送 PATCH 请求。

### 4.5 不做的

- 不做富文本编辑器（幻灯片内容结构简单，纯文本足够）
- 不做手动拖拽排序幻灯片（结构变更走 AI）

## 5. 实现顺序

三个功能按以下顺序实现，每完成一个提交一次：

1. **版本历史 + 回退** — 基础设施改动最大（版本列表 API + 前端版本栏）
2. **素材覆盖分析** — 主要改动在 prompt + 前端提示条，依赖已有的生成结果渲染
3. **轻量文本编辑** — 纯前端交互改动，依赖版本历史作为安全网

## 6. 不涉及的变更

- 不修改现有的分享/发布/采集流程
- 不增加新的数据库表（版本历史复用已有 TrainingPage 和 IterationHistory 表）
- 不修改框架系统
